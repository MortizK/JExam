**JExam Developer Guide**

This guide orients new and returning developers to the JExam codebase, common workflows, verification steps, and maintenance tasks.

**Overview**
- **Project:** JExam — a Java-based exam generation and preview tool using JavaFX and Apache PDFBox.
- **Language & Tooling:** Java (Maven), JavaFX, Apache PDFBox, Python (metrics scripts).
- **Location:** repository root — use `pom.xml` for build tasks and `doc/scripts/collect_metrics.py` to regenerate metrics.

**Prerequisites**
- Java 17+ JDK installed and `JAVA_HOME` set.
- Maven available on PATH (`mvn`).
- Python 3.8+ (optional) for metrics script; recommended to use the provided virtualenv for reproducible runs.

**Quick Commands**
Run these from the repository root.

```bash
mvn clean package
mvn test
# Generate Javadoc (skips tests):
mvn -DskipTests=true javadoc:javadoc
# Start app (dev):
mvn exec:java -Dexec.mainClass=com.jexam.app.Main
# Regenerate metrics report:
python doc/scripts/collect_metrics.py
```

**Repository Layout (high-level)**
- `src/main/java` — application source code.
  - `com.jexam.generation` — PDF generation using PDFBox.
  - `com.jexam.app` — application services, containers, and orchestration.
  - `com.jexam.app.ui.components` — JavaFX visual components and UI widgets.
- `src/test` — unit and integration tests.
- `doc/` — documentation and scripts (including `doc/scripts/collect_metrics.py`).

**Key Components & Where to Start**
- PDF generation: `src/main/java/com/jexam/generation/PdfBoxGenerationService.java` — layout zones, page-break strategy, text wrapping helpers. Use this file when changing visual output or page layout.
- Application orchestration: `src/main/java/com/jexam/app/ExamApplicationService.java` — generation goals, task selection, and dataset workflows.
- XML IO & editor shell: `src/main/java/com/jexam/app/XmlTabContainer.java` — XML loading, validation, and tree mapping flows.
- PDF preview & export: `src/main/java/com/jexam/app/PdfTabContainer.java` — preview rendering, export handlers, and busy-state management.
- UI components: `src/main/java/com/jexam/app/ui/components` — smaller, reusable widgets such as `PreviewRegion`, `GenerationControls`, `BreadcrumbNavigation`, and `ChapterConfigurationComponent`.

**Architecture Notes**
- The app separates concerns across three layers: IO and persistence (XML loader/writer), application logic (generation algorithms, services), and presentation (JavaFX components + PDF rendering).
- PDF rendering is done with Apache PDFBox; layout decisions (margins, columns, box sizes) are encoded in `PdfBoxGenerationService` and should be the primary place for visual changes.
- The generation process is deterministic given a seed — check `ExamApplicationService` for selection policies and cloning logic used to produce variants.

**Development Workflow**
- Branching: use feature branches (`feature/<short-desc>`), open PRs against `main`.
- Commits: describe intent and link related issue or metric changes.
- Fast iteration: to compile quickly without tests, use `mvn -DskipTests=true clean compile` and run only targeted tests with `mvn -Dtest=SomeTest test`.

**Testing & Verification**
- Run the test suite locally: `mvn test`.
- After code changes that affect APIs or public behavior, regenerate and inspect Javadoc:

```bash
mvn -DskipTests=true javadoc:javadoc
```

- Regenerate metrics report to capture size and complexity deltas:

```bash
python doc/scripts/collect_metrics.py
# Output: doc/Metriken.md
```

**Metrics: Objective vs Subjective**
- Objective metrics (generated by `collect_metrics.py`) include file/method counts, physical lines, comment ratios, and a heuristic cyclomatic estimate.
- Subjective metrics are placeholders in `doc/Metriken.md`; maintainers should score and document rationale (architecture clarity, documentation quality, readability, maintainability) in a reviewer file or PR description.

**Common Tasks — Mini Walkthroughs**
- Change PDF layout (example): modify margins or column widths in `PdfBoxGenerationService.java`; run `mvn -DskipTests=true clean package` then produce a sample PDF via the UI export or unit test that covers generation.
- Add a UI control: add component to `com.jexam.app.ui.components`, wire it into `PdfTabContainer` or `XmlTabContainer`, then run the UI via the `exec:java` goal for manual testing and add a unit or integration test under `src/test/java`.

**Troubleshooting**
- Javadoc errors: often caused by unescaped HTML/XML in comments; escape `<`/`>` or enclose examples in {@code ...} blocks.
- PDF layout regressions: create a small dataset covering edge cases (long task descriptions, lots of variants) and run generation to inspect page breaks.
- Metrics script fails: ensure Python 3 and dependencies (none external) and run the script from repo root.

**Maintenance Checklist (suggested PR checklist)**
- Run `mvn test` and ensure tests pass.
- Regenerate Javadoc and ensure no errors: `mvn -DskipTests=true javadoc:javadoc`.
- Regenerate metrics and include a short metrics delta in PR description: `python doc/scripts/collect_metrics.py`.
- Update `doc/Metriken.md` only if the PR changes measurable metrics or if you include a maintained subjective score.

**Where to look for more details**
- See `README.md` for project overview and license.
- Consult the Javadoc output under `target/site/apidocs` after running `mvn javadoc:javadoc`.
- Key source files referenced above are good starting points for deeper investigation.
